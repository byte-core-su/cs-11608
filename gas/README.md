# Apps Script（選用）

這個資料夾有**兩個獨立的 Apps Script 專案**：

- `grader.gs`：同一個部署做兩件事
  1. **作品自動評分**：不用 AI，拿學生的 `.sb3` 和老師的**參考解答**、**空白範本**逐塊比對，自動給星。
  2. **闖關排行賽**：出題、判對錯、量時間、記排行（見最後一節）。
- `classroom.gs`：教師後台「📥 繳交審核」讀 Classroom 的繳交（部署步驟寫在檔案開頭）。

以下說的都是 `grader.gs`。

| 檔案 | 用途 |
|---|---|
| `grader.gs` | 評分服務本體（貼到 Apps Script） |
| `appsscript.json` | 權限設定（貼到 Apps Script 的「appsscript.json」） |
| `classroom.gs` | 繳交審核讀 Classroom（另一個專案，用學校帳號部署） |
| `test.js` | 比對核心的測試：`node gas/test.js`（見下面「測試」） |
| `works.test.js` | 相同作品（指紋、積木編號、取消後擋下）與運算思維截圖的測試：`node gas/works.test.js` |
| `fakegas.js` | 假的 Apps Script（Firestore、登入、快取、鎖、雲端硬碟都在記憶體裡），給上面兩支測試用 |
| `demo/` | 測試用的「示範關卡：購物清單小幫手」解答／空白 `.sb3`（和課程任何一關都無關） |
| `arena.test.js` | 排行賽的測試（假的 Apps Script＋假的 Firestore，從 `doPost` 一路測到寫進資料庫）：`node gas/arena.test.js` |

## 怎麼評分

**範本 ＝ 解答 − 空白。** 空白範本裡你預先放好的積木（鷹架）不算學生的功勞；
解答比空白**多出來的積木**，才是這一關學生該寫的。第 1 關「班級置物櫃」就是 18 塊。

每一塊都比三層：

| 層 | 看什麼 | 分數 |
|---|---|---|
| ① 積木 | 該用的積木有沒有用到、用了幾塊 | 50 |
| ② 位置 | 放在哪個事件底下、包在哪個迴圈／如果裡面 | 30 |
| ③ 設定值 | 清單名稱、數字、文字、按鍵是否和範例一樣（不計大小寫、空白、`3` 和 `3.0`） | 20 |

| 星數 | 條件 |
|---|---|
| **3⭐** | 90 分以上，**而且和範例一致**：每一種積木都有用到、沒有放錯位置、設定值至少八成一樣 |
| **2⭐** | 75 分以上 |
| **0⭐** | 未滿 75 分（未通關） |

學生看到的回饋只說**缺哪種積木、幾塊放錯位置、幾塊設定值不同**，不會直接說出答案的設定值。
可以一直重交，星數只會往上、不會變低。

**實測（第 1 關）**

| 交的東西 | 結果 |
|---|---|
| 解答 | 100 分 3⭐ |
| 空白 | 0 分 0⭐，列出缺的 7 種積木 |
| 清單內容換成別的名字 | 92 分 **2⭐**（設定值只有 61% 一樣） |
| 完全沒用「插入」 | 94 分 **2⭐**，指出缺「插入」 |
| 按鍵全部改成空白鍵 | 89 分 2⭐ |
| 「替換」搬到綠旗底下 | 97 分 **2⭐**（1 塊位置不對） |

⚠️ **它判斷不了程式跑起來對不對**：積木、位置、設定值都和範例一樣，就是滿分。
解法和範例差很多的學生可能被低估——遇到時請打開他的作品看一下（有設定 `DRIVE_FOLDER_ID` 的話，作品都備份在那個資料夾）。

## 範本放在哪

Firestore 的 `{TERM}-grader/criteria` 這份文件（每一學期一份），`units_json` 欄位，每一關有：

- `example_code`：參考解答（虛擬碼）
- `template_code`：空白範本（虛擬碼）

在教師後台的「📗 評分範本」頁上傳 `.sb3`，這支腳本會轉成虛擬碼存進去。

⚠️ 這份文件只有老師讀得到。**解答 `.sb3` 絕對不可以放在網站的資料夾裡**——網站是公開的，
學生下載解答原封不動交上來就是 3⭐。

### 測試

`node gas/test.js` 預設拿 `demo/` 的示範關卡來測：解答 100 分 3⭐、空白 0 分，
換掉設定值、少一種積木、積木放錯位置都只有 2⭐。
示範關卡是專門做給測試用的（購物清單：綠旗建清單、按 a／b／c／d／空白鍵 新增、插入、替換、刪除、重複），
和課程任何一關都無關，公開沒關係；用 Scratch 也打得開，可以拿來看看比對怎麼算分。

想拿自己的某一關來測，指定一個**網站以外**的資料夾和關卡代號：

```
node gas/test.js D:\教材\scratch 01_
```

資料夾裡放檔名含「01_」的「解答」「空白」兩個 `.sb3`。

## 部署（約 10 分鐘）

1. 用**老師的 Google 帳號**（就是建立 Firebase 專案的那一個）打開 [script.google.com](https://script.google.com) → 新增專案。
2. 把 `grader.gs` 整份貼進 `程式碼.gs`。
3. 專案設定（齒輪）→ 勾「在編輯器中顯示 appsscript.json」→ 回編輯器，把 `appsscript.json` 整份貼上。
4. 專案設定 → **指令碼屬性**，新增：

   | 屬性 | 值 |
   |---|---|
   | `PROJECT_ID` | Firebase 專案 ID（`config.js` 的 `FIREBASE.projectId`） |
   | `API_KEY` | `config.js` 的 `FIREBASE.apiKey` |
   | `TEACHER_EMAIL` | 教師帳號（和 `config.js` 一樣，小寫） |
   | `TERMS` | 學期代號，逗號分隔（和根目錄 `config.js` 的 `TERMS` 一樣，例如 `11501,11502`）。不填就是 `11501,11502`。每個請求都會帶上學期，不在這份清單裡的一律拒絕 |
   | `SID_PATTERN` | 選填，學號格式，預設 `^\d{7}$` |
   | `DRIVE_FOLDER_ID` | 選填，作品備份和運算思維通關截圖要存到哪個雲端硬碟資料夾（網址最後那一串）。沒填：作品不備份、截圖不保存 |

5. **部署 → 新增部署作業 → 類型選「網頁應用程式」**：執行身分「**我**」，存取權「**所有人**」→ 部署 → 授權。
6. 複製結尾是 `/exec` 的網址，貼到根目錄 `config.js` 的 `GRADER_URL`（兩學期共用這一個網址）。

**確認有沒有成功**：瀏覽器直接打開那個 `/exec` 網址，看到 `{"ok":true,"version":"grader-…"}` 就對了。

⚠️ 之後改了 `grader.gs`，要「部署 → 管理部署作業 → 編輯 → 版本選**新版本**」，線上才會換。
選成「現有版本」的話程式改了也沒用，而且不會有任何錯誤訊息。

⚠️ 用「老師的身分」執行是刻意的：星數要用學生改不到的身分寫進資料庫。
**Google 帳號一定要是 Firebase 專案的擁有者或編輯者**，不然寫不進去。

## 為什麼學生偽造不了分數

1. 送作品時附上 Firebase 的登入憑證，腳本向 Firebase 確認「真的是學號 X 本人」。
2. 星數由腳本以老師的身分寫進 Firestore；安全規則不准學生自己改作品星。
3. 抄別人的作品：見下一節「相同作品」。

## 相同作品（抄襲的線索）

**比對不在上課時做。** 學生交作品時，評分服務只順手多記兩樣東西（寫進本來就要寫的那筆進度，不多一次連線）；
老師打開「🐱 作品評分」時，才在老師的電腦上比對全年級。

| 線索 | 怎麼來 | 抓得到 |
|---|---|---|
| 指紋 | 作品內容的雜湊 | 整個檔案原封不動轉傳 |
| 積木編號 | 每塊積木的編號（Scratch 建立積木時隨機產生，複製檔案會一直跟著，拖動、改數字都不會變） | 拿別人的檔案拖一下、改個數字再交 |

- 兩個學生各自做出一模一樣的程式**不會**被標出來：自己拖出來的積木編號都不一樣。
- 空白範本的積木大家都有，比對時扣掉（在「📗 評分範本」**重新上傳一次空白範本**，系統才記得住它的積木）；
  這一關一半以上的人都有的積木也扣掉（大家共同的起始檔）。
- 記的是「拿到目前星數的那一份」：抄來 3⭐ 之後再交一份差的，蓋不掉抄來的那一份。
- **取消成績**：那一關改成 0⭐，記下那一份的指紋與特有的積木編號。之後同一份、或改一點點再交 ⇒ 擋下並告訴學生
  「請自己重新做一份」；自己重做的照常評分。取消錯了可以「撤銷取消」。
- ⚠️ 只看得出「誰和誰一樣」，看不出誰抄誰；整份重新拖一遍的抄法也抓不到。

## 運算思維的通關截圖

設了 `DRIVE_FOLDER_ID`，學生在運算思維頁過關時，截圖會在**背景**送到這裡（過關照常馬上記錄，送不上去也不影響過關）：

- 存在 `DRIVE_FOLDER_ID / 學期 / thinking / 班級 / 班級座號_姓名_學號_第NN關.png`
- 超過 4 MB 的截圖，學生的瀏覽器會先縮成 1920 像素寬的 JPG（約 0.2～0.5 MB）；上限 8 MB
- 同一關換一張 ⇒ 舊的丟進雲端硬碟的垃圾桶（30 天內救得回來）；同一張重傳 ⇒ 不再存一份
- 後台「🧠 通關截圖」看每一關的截圖；同一張圖交兩次以上（同一人交兩關、或兩人交同一張）會標 👯，也是打開時才比對
- 系統**不判讀**截圖的內容（有沒有「挑戰成功」），只是存起來給你看

## 用量

一份作品解析不到 1 秒。Apps Script 同時最多處理 30 個請求，一個班一起交沒問題。

## 闖關排行賽

規則：20 題、★1 起跳、答對升一級答錯降一級，全對 1000 分；
每題限時 20 秒、作答中離開畫面算答錯；一天 2 次（按開始就算一次）；全期取最高分，同分用時短的在前；
那一學期的章節測驗 10 章全部通關才能玩；難度依全班的答對率每天分一次。

**開始前**：教師後台「🏆 排行賽」→ 按**匯入題庫**（老師的瀏覽器從那一學期的題庫檔抽出題目送過來：
上學期 `11501/content/ethics.js`、下學期 `11502/content/social.js`）。**切換學期各匯一次**；兩學期的題庫、排行、次數都分開記。
沒匯入的話，學生按開始會看到「題庫還沒匯入，請告訴老師」。

**學生作弊不了分數**：題目由這裡出、選項由這裡洗、對錯由這裡判、時間由這裡量（頁面改掉倒數也沒用），
瀏覽器只送「選了第幾個」；成績用老師的身分寫進 Firestore，學生讀寫不到。
⚠️ 題目和答案雜湊本來就在題庫檔裡（章節測驗要用）、是公開的——排行賽沒有多洩漏任何東西，擋的是改分數、拖時間、換題目。

**幾個細節**

- 寬限時間 **8 秒**：Apps Script 冷啟動要 2～4 秒，避免準時作答被誤判超時。
- 進行中的那一場放在 Apps Script 快取，一小時沒動才丟。
- 學生斷線白白用掉一次：後台「退回 1 次」。

**用量**：每答一題約 1 秒來回（倒數不受影響——時間從出題那一刻起算，另有寬限）。
每天第一個按開始的人要等全班統計算分級，可能 5～10 秒（頁面有提示，之後一整天都很快）。
Apps Script 同時最多 30 個請求：一個班一起玩沒問題，全年級同時開始會有人要多等幾秒。
